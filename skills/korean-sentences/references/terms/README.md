# 한국 개발자 용어

글에 개발 용어를 쓸 때 한국 개발자가 실제로 쓰는 말을 고르기 위한 목록이다. 규칙 1-3이 이 디렉터리를 가리킨다.

우리말로 옮기면 쉬워 보여도, 개발자가 쓰지 않는 말이면 오히려 읽기 어렵다. 예를 들어 "통합 시험", "orders 표", "공개 client"는 한 번 더 영어로 되돌려 읽어야 뜻이 잡힌다.

## 고르는 순서

1. **목록에 있으면 "쓰는 말"을 그대로 쓴다.** 쓰는 말은 영어 그대로일 수도 있고(Client ID), 한글로 바꾼 말일 수도 있다(테이블, 인증). 대소문자와 띄어쓰기도 표에 적힌 대로 쓴다.
2. **코드에 나오는 값·키·클래스는 백틱으로 원문 그대로 쓴다.** 예: `client_id`, `grant_type=client_credentials`, `SecurityFilterChain`
3. **목록에 없으면 원문에 쓴 말을 그대로 둔다.** 혼자 새 번역어를 만들지 않고, 따로 묻지도 않는다. 목록은 사용자가 글을 읽다가 이상하다고 짚은 말만 더한다.

같은 글 안에서 한 낱말을 두 뜻으로 쓰지 않는다. 예: "대역"을 테스트용 가짜 구현과 VPC IP 범위에 함께 쓰는 경우

## 우선순위

같은 말이 여러 곳에 있거나, 한 말이 다른 말을 품고 있으면 아래 순서로 고른다.

**문서 순서: 좁은 범위의 문서를 먼저 본다.**

1. 프로젝트 용어집: 그 프로젝트가 이름을 붙인 말. 예: 그 프로젝트의 문서나 노트가 따로 정해 둔 기능·개념 이름
2. 글이 다루는 영역의 파일. 예: `auth-oauth.md`
3. `common.md`

프로젝트 용어집은 글이 속한 프로젝트에서 찾는다. 예: 저장소의 `docs/glossary.md`, 문서 폴더의 용어집 페이지, 노트 묶음의 약어 표. 없으면 이 단계를 건너뛴다.

**낱말 순서: 긴 말을 먼저 맞춘다.**

- 글의 말이 표의 긴 말과 맞으면, 그 안에 든 짧은 말보다 긴 말을 따른다.
  - "client id"는 client(클라이언트)보다 Client ID를 먼저 본다. ○ Client ID ✗ 클라이언트 id
  - "refresh token rotation"은 rotation보다 리프레시 토큰 로테이션을 먼저 본다.
- 표 안의 순서나 파일 순서와 상관없이 긴 말이 이긴다. `common.md`의 짧은 말과 영역 파일의 긴 말이 겹쳐도 같다.

## 파일

용어는 영역마다 다를 수 있으므로 영역별 파일로 나눈다. `common.md`는 영역과 상관없이 쓰는 낱말이라 언제나 읽는다. 영역 파일 목록과 각 파일을 읽게 하는 키워드는 `korean-sentences`의 `SKILL.md` 2단계 표에 있다. 글의 주제가 하나여도 걸리는 영역은 여럿일 수 있다. 예를 들어 Spring Security 필터 체인 글에 "토큰"이 나오면 `spring.md`와 `auth-oauth.md`를 함께 읽는다.

키워드를 더할 때는 아래를 지킨다.
- 그 영역에만 나오는 말을 고른다. "설정", "서버"처럼 어디에나 나오는 말은 넣지 않는다.
- 영어와 한글을 함께 적는다. 예: JWT와 토큰
- 코드에 나오는 이름도 적는다. 예: `@Transactional`, `SELECT`

영역 파일은 두 부분으로 쓴다.

- **용어 표:** "영어 | 쓰는 말" 두 칸. 쓰는 말이 여럿이면 앞의 것을 먼저 고른다. 뜻이 헷갈리는 말에만 표 아래에 짧게 적는다.
- **고칠 때 찾아볼 말:** 실제 글에서 이상하게 옮긴 예시다. "찾아볼 말 | 바꿀 말" 두 칸으로 쓴다. 이미 쓴 글을 고칠 때 이 말들을 먼저 찾는다. 찾은 곳이 모두 틀린 것은 아니다. 예를 들어 문서 안의 표는 "표"가 맞다. 그래서 찾은 곳마다 맥락을 보고 정한다.

## 고치는 법

- 이 디렉터리는 `korean-sentences-rules`가 고친다. `korean-sentences`는 읽기만 한다.
- 새 용어는 실제 글에서 어색했던 말에서만 더한다. 어디서 나왔는지는 `../cases.md`에 사례로 남긴다.
- 잘못 옮긴 말을 만나면 그 말을 "고칠 때 찾아볼 말"에도 더한다.
- 쓰는 사람마다 갈리는 말은 사용자와 논의한 뒤에 정한다.
- 새 영역 파일을 만들면 `SKILL.md` 2단계 표에 한 줄 더한다.
- 업무 도메인 용어(예: 주문, 정산 같은 업무 용어)는 이 디렉터리에 넣지 않는다. 프로젝트 용어집을 따른다.
