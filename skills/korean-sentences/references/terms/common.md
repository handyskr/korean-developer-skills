# 공통 개발 용어

| 영어 | 쓰는 말 |
|---|---|
| test | 테스트 |
| integration test | 통합 테스트 |
| unit test | 단위 테스트 |
| test double | 테스트 대역 |
| fake | 페이크 |
| stub | 스텁 |
| resource | 리소스 |
| cache | 캐시 |
| TTL | TTL |
| rotation | 로테이션 |
| revoke | 폐기 |
| invalidate | 무효화 |
| encrypt | 암호화 |
| decrypt | 복호화 |
| decode | 디코딩 |
| decoder | 디코더 |
| random | 랜덤 |
| rate limit | 요청 제한 |
| IP address | IP |
| start up | 시작, 구동 |
| format | 형식 |
| structure | 구조 |
| endpoint | 엔드포인트 |
| API endpoint (하나하나를 셀 때) | API, 엔드포인트 |
| log scale | 로그 스케일 |
| scale | 스케일 |
| health check | 헬스 체크 |
| HTTP status code | status code |
| version | 버전 |

- 테스트 대역: "대역"만 따로 쓰지 않는다. IP 범위의 "대역"과 겹친다.
- 디코딩과 복호화는 다르다. JWT 서명을 확인하는 `JwtDecoder`는 디코더다.
- API: 하나하나의 API를 "경로"라고 부르지 않는다. "경로"는 URL 경로를 말할 때만 쓴다. ○ 읽기 API 네 개 ✗ 읽기 경로 네 개
- IP: "요청 주소"라고 쓰지 않는다. "주소"는 URL과 겹친다.
- 버전: 판(版)으로 옮기지 않는다. ○ 새 버전, 고치기 전 버전 ✗ 새 판, 고치기 전 판. 다만 프로젝트 용어집이 "판"을 이름으로 정해 둔 말은 그 이름을 따른다.
- status code: 응답을 말할 때는 "status code 400으로 응답합니다"처럼 쓴다. "400을 냅니다"처럼 숫자만 목적어로 두지 않는다. 표 칸에서는 숫자만 써도 된다.

## 고칠 때 찾아볼 말

| 찾아볼 말 | 바꿀 말 |
|---|---|
| 시험, 통합 시험 | 테스트, 통합 테스트 |
| 대역 (테스트용 가짜 구현) | 페이크, 테스트 대역 |
| 자원 | 리소스 |
| 보관 (캐시 뜻) | 캐시 |
| 회전 | 로테이션 |
| 끊기, 끊김 (토큰·키) | 폐기 |
| 감싸다 (암호화 뜻) | 암호화하다 |
| 풀다 (복호화 뜻) | 복호화하다 |
| 복호기 | 디코더 |
| 무작위 | 랜덤 |
| 상한 (요청 수) | 요청 제한 |
| 요청 주소 (IP 뜻) | IP, 클라이언트 IP |
| 기동 | 시작 |
| 모양 (형식 뜻) | 형식, 구조 |
| 로그 눈금 | 로그 스케일 |
| 소관 | 관리 |
| 경로 (API 하나하나를 뜻할 때) | API |
| 400을 내다, 400을 냅니다 (응답 뜻) | status code 400으로 응답합니다 |
| 판, 새 판, 첫 판 (버전 뜻) | 버전, 새 버전, 첫 버전 |
