# 한국 개발자용 문장 규칙

## 목차

- 범위
- 1. 낱말: 1-1 묶어 부르는 말, 1-2 동사, 1-3 개발 용어
- 2. 수와 묶음: 2-1 단위, 2-2 하는 일로 묶기, 2-3 꾸밈말, 2-4 금액·수치 문장
- 3. 문장과 문단의 순서: 3-1 개요 먼저, 3-2 묶음 이름 먼저, 3-3 조각 문장
- 4. 말투: 4-1 합니다체, 4-2 "~할 겁니다", 4-3 표 칸과 그림 글씨, 4-4 한 이름, 4-5 제목은 명사로, 4-6 사실 목록은 명사로
- 5. 표기: 5-1 괄호 설명, 5-2 조사 붙여 쓰기, 5-3 의존 명사
- 마지막 점검

## 범위

이 파일은 사람이 읽는 결과물 가운데 **글**을 다룬다.

| 든다                               | 아직 들지 않는다      |
| -------------------------------- | -------------- |
| 문서·노트·대화의 문장과 문단 순서              | 차트 종류, 그림 모양   |
| 대시보드·표의 글자와 그림 글씨 (제목, 설명, 라벨, 범례) | 배치, 여백, 색      |
| 슬라이드 안의 글자                       | 슬라이드 구성과 장 나누기 |

그림 모양·배치·슬라이드 규칙은 범위를 넓힐 때 따로 만든다.

규칙마다 ✗ 나쁜 예와 ○ 좋은 예를 둔다. 새 규칙은 실제로 어색했던 문장에서만 만든다. 그 문장은 `cases.md`에 사례로 남긴다.

- 이 파일을 읽고 적용하는 스킬: `korean-sentences`
- 개발 용어 목록: `references/terms/` (규칙 1-3)
- 규칙이 생긴 사례: `cases.md`. 규칙을 적용할 때는 읽지 않아도 된다.
- 이 파일을 고치는 스킬: `korean-sentences-rules`. korean-sentences가 고친 문장을 사용자가 여전히 어색하다고 할 때만 고친다. 규칙 번호는 사례가 가리키므로 바꾸지 않는다. 새 규칙은 묶음 끝에 다음 번호로 붙인다.

## 1. 낱말

**1-1. 묶어 부르는 말은 개발자가 실제로 쓰는 말로 쓴다**
- ✗ 부품: 기계에 빗댄 말이다.
- ✗ 모듈: 클래스나 인터페이스를 가리킬 때는 틀린 말이다. 개발자는 Gradle·Maven 모듈로 읽는다.
- ○ 구성 요소, 클래스, 인터페이스. 마땅한 말이 없으면 "일곱 가지"처럼 이름 없이 센다.

**1-2. 동사는 무엇을 어떻게 하는지 드러나게 쓴다**
- ✗ 채운다, 판정한다, 결과를 담는다
- ○ 알아서 처리한다, 권한이 있는지 확인한다, 인증 결과를 담아 둔다

**1-3. 개발 용어는 한국 개발자가 실제로 쓰는 말로 쓴다**
- 용어 목록은 `references/terms/`에 영역별로 있다. `common.md`와 글이 다루는 영역의 파일을 따른다.
- 쓰는 말은 영어 그대로일 수도 있고, 한글로 바꾼 말일 수도 있다. 쉬운 우리말로 옮긴다고 읽기 쉬워지지 않는다.
- ✗ 통합 시험, orders 표, 공개 client, client 비밀, refresh 회전
- ○ 통합 테스트, orders 테이블, Public Client, Client Secret, 리프레시 토큰 로테이션
- 목록에 없는 용어는 원문에 쓴 말을 그대로 둔다. 새 번역어를 만들지 않는다. 목록은 사용자가 이상하다고 짚은 말만 더한다.

## 2. 수와 묶음

**2-1. 수를 셀 때는 단위를 붙인다**
- ✗ 일곱이다, 앞의 셋이다
- ○ 일곱 가지입니다, 세 개입니다

**2-2. 앞·뒤 같은 위치 말로 묶지 말고, 하는 일로 묶는다**
- ✗ 앞의 셋, 뒤의 넷: 무엇의 앞인지 읽는 사람이 알 수 없다.
- ○ 인증 쪽, 권한 쪽

**2-3. 꾸밈말은 묶은 항목 모두에 맞아야 한다**
- ✗ 메서드 앞에서 실행되는 A, B, C, D: C와 D는 메서드 앞에서 실행되지 않는다.
- ○ 하나라도 맞지 않으면 묶음을 나눈다. 성격이 다른 항목은 "~가 있고, ~도 있습니다"로 따로 말한다.

**2-4. 금액·수치 문장은 무엇의 값인지를 주어로 먼저 쓴다**
- 금액을 주어로 세우면 무엇의 금액인지 빠져 문장이 비어 보인다. "비용이 들다", "요금이 나오다" 자체는 자연스러운 우리말이다.
- ✗ 스토리지 비용까지 합쳐 $45가 들었습니다.
- 글의 쓰임에 따라 꼴을 고른다.
  - 보고서·문서·대시보드: ○ 스토리지를 포함한 총비용은 $45입니다. ○ 운영 비용은 스토리지 및 전송 비용을 포함하여 총 $45가 소요되었습니다.
  - 대화·공유: ○ 비용은 인스턴스와 스토리지를 모두 합쳐서 총 $45 들었습니다. ○ 인스턴스랑 스토리지 다 합해서 $45 정도 나왔습니다.
- "들다", "나오다"로 받을 때는 금액에 "가"를 붙이지 않는다. ✗ $45가 들었습니다 ○ 총 $45 들었습니다
- 합친 값에는 "총"이나 "총비용"을 써서 합계라는 것을 드러낸다.
- 앞뒤 문장이 같은 값을 말하면 주어를 같게 둔다. ○ "… 총비용은 $45였습니다. 모두 온디맨드로 돌렸다면 총비용은 $90 ~ $110였을 것으로 추정합니다."
- 기간을 합친 값에는 "9월 현재"처럼 한 시점을 뜻하는 말을 쓰지 않는다. ○ 9월에는

## 3. 문장과 문단의 순서

**3-1. 개요를 먼저 말하고, 다음 문단에서 하나씩 푼다**
- 첫 문단에서는 전체 수와 나누는 기준을 말한다. 그다음 묶음마다 문단을 하나씩 쓴다.
- ✗ 한 문장에 일곱 개를 모두 늘어놓는다.
- ○ 일곱 가지입니다. 인증 쪽에서 세 가지, 권한 쪽에서 네 가지를 다룹니다. (다음 문단) 우선 인증 쪽은 …

**3-2. 묶음 이름을 먼저 쓰고, 목록은 뒤에 쓴다**
- ✗ A, B, C가 앞의 셋이다. 목록을 끝까지 읽어야 무엇인지 알 수 있다.
- ○ 인증 쪽은 A, B, C입니다.

**3-3. 명사로 끊긴 조각 문장을 쓰지 않는다**
- ✗ 인증 쪽에서 세 가지. 권한 쪽에서 네 가지를 다룹니다.
- ○ 인증 쪽에서 세 가지, 권한 쪽에서 네 가지를 다룹니다.
- 문단 안의 문장에 적용한다. 사실을 나열하는 목록 항목은 4-6을 따른다.

## 4. 말투

**4-1. 설명하는 글은 합니다체로 쓴다**
- ✗ 일곱 가지다. 다룬다.
- ○ 일곱 가지입니다. 다룹니다.

**4-2. 글에서는 "~할 겁니다" 대신 "~합니다"를 쓴다**
- ✗ 네 가지를 다룰 겁니다.
- ○ 네 가지를 다룹니다.

**4-3. 표 칸과 그림 글씨는 짧게 둔다**
- 표 칸과 그림 글씨는 합니다체로 바꾸지 않는다. 명사형이나 "~한다"로 짧게 끝낸다.
- 낱말, 수 세기, 조사 붙여 쓰기 규칙은 표와 그림에도 똑같이 지킨다.

**4-4. 같은 것은 한 이름으로 부른다**
- 글 하나 안에서 한 대상을 두 이름으로 부르지 않는다. 이름을 바꿀 때는 제목, 표 머리, 그림 글씨까지 함께 바꾼다.
- ✗ 결론에는 "거절", 본문에는 "거부"
- ○ 처음부터 끝까지 "거절"

**4-5. 제목은 명사로 끝낸다**
- 문서 제목, 절 제목, PR·이슈 제목처럼 글의 머리에 다는 한 줄을 말한다.
- "~한다", "~합니다"로 끝내면 본문 문장이나 선언처럼 읽힌다. 우리말 종결 어미는 듣는 사람을 얼마나 높이는지를 함께 정하는데, 제목에는 말을 건네는 상대가 없다. 끝난 작업에 현재형을 붙이면 앞으로 할 일처럼 읽히기도 한다.
- ✗ 도서 검색에 저자 이름 필터를 더하고 응답도 그에 맞게 바꾼다
- ○ 도서 검색의 저자 이름 필터 추가와 응답 형식 개편
- 동작을 드러내야 하면 "~하기"로 끝낸다. ○ 도서 검색에 저자 필터 더하기
- 묻는 꼴의 절 제목은 써도 된다. ○ 왜 인덱스를 두 개 거는가
- 저장소 규칙이 제목 꼴을 따로 정해 두었으면 그 규칙을 따르고, 이 규칙과 어긋난다고 사용자에게 알린다. 예: 커밋 제목을 "~한다"로 끝내게 정한 저장소

**4-6. 사실을 나열하는 목록 항목은 명사로 끝내도 된다**
- 무엇을 더했는지, 어디에 두었는지처럼 사실만 늘어놓는 목록을 말한다. 4-5와 같은 까닭으로, 말을 건네는 문장이 아니어서 명사로 짧게 끝내는 쪽이 더 잘 읽힌다.
- 한 목록 안에서는 끝맺음을 하나로 맞춘다.
- ✗ - 저자 이름 필터를 더했습니다 / - 응답에 출판 연도 추가 / - `book` 테이블에 인덱스를 겁니다
- ○ - 저자 이름 필터 추가 / - 응답에 출판 연도 추가 / - `book` 테이블에 인덱스 추가
- 까닭을 말하거나 무엇을 부탁하는 항목은 문장으로 쓴다. 명사로 끝내면 까닭과 부탁이 빠진다.
  - ✗ - 권한 확인 일치 여부
  - ○ - 목록과 상세의 권한 확인이 같은지 봐 주세요. 상세만 관리자 권한을 따로 확인합니다.

## 5. 표기

**5-1. 문장 안에 괄호 설명을 되풀이하지 않는다**
- ✗ A (인터페이스), B (인터페이스), C (클래스)
- ○ 종류는 표에 따로 적거나 한 문장으로 모은다.

**5-2. 조사는 영어 낱말과 코드에 붙여 쓴다**
- ✗ Spring이, `SecurityContextHolder`가
- ○ Spring이, `SecurityContextHolder`가

**5-3. 의존 명사는 띄어 쓴다**
- ○ 봐야 할, 세 가지, 네 개, 맨 앞, 할 수, 담아 두는

## 마지막 점검

옆자리 개발자에게 말로 설명할 때도 이 문장을 그대로 쓸지 생각해 본다. 그대로 말하지 않을 문장이면 고친다.
