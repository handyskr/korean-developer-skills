# 규칙이 생긴 사례

규칙(`rules.md`)이나 용어 목록(`terms/`)을 고치게 만든 실제 문장을 모은다. 규칙 번호는 `rules.md`의 번호를 가리킨다. `korean-sentences-rules`가 규칙을 고칠 때 읽고, 새 사례를 맨 아래에 더한다.

## 목차

- 사례 1. Spring Security 구성 요소 소개
- 사례 2. 대시보드 머리 요약의 금액 문장
- 사례 3. OAuth 2.0 학습 페이지의 개발 용어
- 사례 4. PR 요약의 DB 인덱스 이름
- 사례 5. 응답 상태를 말하는 문장
- 사례 6. API를 "경로"로 부른 문장
- 사례 7. "~한다"로 끝낸 PR 제목
- 사례 8. 사실 목록까지 문장으로 쓰게 한 안내

### 사례 1. Spring Security 구성 요소 소개 (2026-10-29)

고치기 전:

> 우리가 손대는 부품은 일곱이다. 체인을 만드는 SecurityFilterChain (인터페이스) 빈, 인증을 하는 AuthenticationProvider (인터페이스), 결과를 담는 SecurityContextHolder (클래스) 가 앞의 셋이다. 메서드 앞에서 판정하는 @PreAuthorize (어노테이션) 와 AuthorizationManager (인터페이스), 거부를 401·403 으로 바꾸는 AuthenticationEntryPoint (인터페이스) 와 AccessDeniedHandler (인터페이스) 가 뒤의 넷이다. 그 밖의 부품은 Spring이 채운다.

고친 뒤:

> 이 장에서 직접 봐야 할 구성 요소는 일곱 가지입니다. 인증 쪽에서 세 가지, 권한 쪽에서 네 가지를 다룹니다.
>
> 우선 인증 쪽은 필터 체인을 만드는 `SecurityFilterChain` 빈, 사용자가 누구인지 확인하는 `AuthenticationProvider`, 인증 결과를 담아 두는 `SecurityContextHolder`입니다.
>
> 권한 쪽에는 메서드가 실행되기 전에 권한을 확인하는 `@PreAuthorize`와 `AuthorizationManager`가 있고, 거절된 요청을 401·403 응답으로 바꾸는 `AuthenticationEntryPoint`와 `AccessDeniedHandler`도 있습니다.
>
> 나머지는 Spring이 알아서 처리합니다.

걸린 규칙: 1-1, 1-2, 2-1, 2-2, 2-3, 3-1, 3-2, 4-1, 5-1, 5-2

### 사례 2. 대시보드 머리 요약의 금액 문장 (2026-10-29)

고치기 전:

> 9월 이미지 변환 작업의 80% 가 스팟 인스턴스에서 돈다. 7월의 1.5배 일을 스토리지까지 넣어 $45 에 했고, 전부 온디맨드였다면 $90 ~ $110 였다(추정).

처음 고친 문장:

> 9월 이미지 변환 작업의 80%를 스팟 인스턴스에서 처리합니다. 작업량은 7월의 1.5배로 늘었지만, 스토리지 비용까지 합쳐 $45가 들었습니다. 모두 온디맨드로 돌렸다면 $90 ~ $110가 들었을 것으로 추정합니다.

최종:

> 9월에는 이미지 변환 작업의 80%를 스팟 인스턴스에서 처리했습니다. 작업량은 7월의 1.5배로 늘었지만, 스토리지를 포함한 총비용은 $45였습니다. 모두 온디맨드로 돌렸다면 총비용은 $90 ~ $110였을 것으로 추정합니다.

처음 고친 문장이 어색했던 까닭: 금액을 주어로 세우고 "들었습니다"로 받아, 무엇의 금액인지 빠졌다.

정한 것: 금액 문장은 "비용은"이나 "총비용은"을 주어로 세운다. "들다"는 금지하지 않고, "들다"로 받을 때는 금액에 "가"를 붙이지 않는다. 대화용과 보고서용 꼴을 나누고, 대시보드는 보고서용 꼴을 쓴다. 기간을 합친 값의 시점 표현은 "9월에는"처럼 쓴다.

원인: 규칙이 없었다. 더한 규칙: 2-4. 검사: 처음에는 `check.py`에 넣었다가, "봉투에 $10가 들어 있다"처럼 맞는 문장도 잡아서 뺐다. 지금은 korean-sentences의 "직접 읽고 확인한다" 단계에서 본다.

### 사례 3. OAuth 2.0 학습 페이지의 개발 용어 (2026-10-30)

대상: OAuth 2.0 규격을 정리한 학습 페이지 (HTML)

고치기 전:

> 토큰·introspection·revocation endpoint에서는 비밀 client가 Basic으로 증명합니다.

고친 뒤:

> 토큰·Introspection·Revocation 엔드포인트에서는 Confidential Client가 Basic 인증으로 Client Secret을 보냅니다.

같은 페이지에서 걸린 말: 통합 시험, 표(DB 테이블), 줄(행), 열(컬럼), 회전, 가족, 끊기, 자원, 보관(캐시), 잠금, 복호기, 감싸다·풀다, 상한, 요청 주소, 대역, 기동, 모양, 문제 응답, access 토큰·refresh·client·code를 영어 낱말로 두고 조사를 붙인 것

어색했던 까닭: 개발 용어를 우리말로 옮기거나 영어와 반씩 섞어, 읽는 사람이 영어로 되돌려야 뜻이 잡혔다. "대역"과 "주소"는 한 글 안에서 두 뜻으로 쓰였다.

정한 것: Client ID처럼 규격에 정해진 이름은 영어 그대로 쓴다. 용어는 기술 영역마다 다를 수 있으므로 영역별 파일로 나눈다. 표는 "영어 | 쓰는 말" 두 칸으로 두고, 쓰는 말에는 영어 그대로나 한글로 바꾼 말이 모두 올 수 있다. 영역 파일마다 실제로 이상하게 옮긴 예시를 "고칠 때 찾아볼 말"로 따로 둔다. 문서는 프로젝트 용어집, 영역 파일, common 순서로 보고, 낱말은 긴 말(Client ID)을 짧은 말(client)보다 먼저 맞춘다.

원인: 규칙이 없었다. 쉬운 우리말로 쓰려다 개발 용어까지 우리말로 옮겼다. 더한 규칙: 1-3, 용어 목록 `references/terms/`. 검사: "시험", "표"는 맞는 쓰임도 많아 `check.py`에 넣지 않았다. korean-sentences의 "직접 읽고 확인한다" 단계에서 본다.

### 사례 4. PR 요약의 DB 인덱스 이름 (2026-11-03)

대상: PR 본문의 사람용 요약

고치기 전:

> 유일 인덱스 두 개(마이그레이션 `V3`): `isbn`과 (저자, 제목).

처음 고친 문장:

> 마이그레이션 `V3`가 `book` 테이블에 유일 인덱스 두 개를 겁니다.

최종:

> 마이그레이션 `V3`가 `book` 테이블에 UNIQUE INDEX 두 개를 겁니다.

어색했던 까닭: 개발자는 SQL 키워드 그대로 UNIQUE INDEX라고 부른다. "유일 인덱스"는 영어로 되돌려 읽어야 뜻이 잡힌다. 문장 구조는 고쳤지만 낱말은 목록에 없어 원문 그대로 남았다.

원인: 개발 용어가 목록에 없었다. 고친 것: `terms/database.md`에 unique index → UNIQUE INDEX, 고칠 때 찾아볼 말에 "유일 인덱스"를 더했다. 규칙 1-3 은 그대로다. 검사: "유일한 클래스"처럼 맞는 쓰임이 있어 `check.py`에 넣지 않았다.

### 사례 5. 응답 상태를 말하는 문장 (2026-11-03)

대상: PR 본문의 사람용 요약

고치기 전:

> 검색 API의 빈 검색어 거절은 기존 오류 문구(400)로 냅니다.

처음 고친 문장:

> 검색 API는 검색어가 비어 있으면 기존 오류 문구로 400을 냅니다.

최종:

> 검색 API는 검색어가 비어 있으면 기존 오류 문구와 함께 status code 400으로 응답합니다.

어색했던 까닭: "400을 냅니다"는 400이 무엇인지(status code인지 에러 코드인지)와 무엇을 하는지(응답)가 빠졌다.

고른 꼴: "status code 400으로 응답합니다", "400 에러를 반환합니다", "상태 코드 400으로 응답합니다" 가운데 "status code 400으로 응답합니다"를 골랐다. 무엇을 어떻게 돌려주는지가 가장 분명하다.

원인: 개발 용어가 목록에 없었다. 고친 것: `terms/common.md`에 HTTP status code → status code와 쓰는 법, 고칠 때 찾아볼 말에 "400을 내다"를 더했다. 검사: 숫자와 "냅니다"의 조합은 맞는 쓰임("세금 400을 냅니다")이 있어 `check.py`에 넣지 않았다.

### 사례 6. API를 "경로"로 부른 문장 (2026-11-03)

대상: 작업 범위를 정하는 HTML 결정 페이지

고치기 전:

> 네 경로 모두 다른 모듈의 자원(대출, 예약)을 함께 사용해서, 이번 작업에서 옮기지 않게 정합니다.

처음 고친 문장:

> 네 경로는 모두 다른 모듈의 리소스(대출, 예약)를 함께 씁니다. 그래서 이번 작업에서는 옮기지 않습니다.

최종:

> 네 API는 모두 다른 모듈의 리소스(대출, 예약)를 함께 씁니다. 그래서 이번 작업에서는 옮기지 않습니다.

어색했던 까닭: "경로"가 API를 뜻하는지 읽히지 않았다. 개발자는 "경로"를 파일 경로나 URL 경로로 먼저 읽는다. 같은 페이지에서 "경로를 짧게 둔다"는 URL 경로를 뜻해서, 한 낱말이 두 뜻으로 쓰였다(1-3). 프로젝트 문서가 이 쓰임을 많이 썼지만 용어집에 오른 말은 아니어서 프로젝트 용어로 보지 않았다.

정한 것: 하나하나의 API는 "API"로 부른다. "엔드포인트"도 맞지만 셀 때 길어진다. "경로"는 URL 경로를 말할 때만 쓰고, 헷갈리면 "URL 경로"라고 쓴다.

원인: 개발 용어가 목록에 없었다. 고친 것: `terms/common.md`에 API endpoint → API, 엔드포인트와 쓰는 법, 고칠 때 찾아볼 말에 "경로 (API 뜻)"를 더했다. 검사: "경로"는 URL 경로나 파일 경로로 맞게 쓰는 일이 많아 `check.py`에 넣지 않았다.

### 사례 7. "~한다"로 끝낸 PR 제목 (2026-11-04)

대상: PR 제목

고치기 전:

> feat(book): 검색에 저자 필터를 더하고 응답을 맞춘다

처음 고친 문장:

> feat(book): 도서 검색에 저자 이름 필터를 더하고 응답도 그에 맞게 바꾼다

최종:

> feat(book): 도서 검색의 저자 이름 필터 추가와 응답 형식 개편

어색했던 까닭: 제목이 "~바꾼다"로 끝나 본문 문장이나 선언처럼 읽혔다. 종결 어미 "-ㄴ다"는 해라체라 높임 등급을 고르게 되는데, 제목에는 말을 건네는 상대가 없다. 끝난 작업에 현재형이 붙어 앞으로 할 일처럼 읽히기도 했다. 처음 고칠 때는 4-3이 짧은 글을 "명사형이나 '~한다'로" 끝내도 된다고 해서 끝맺음을 그대로 두었다.

정한 것: 제목은 명사로 끝내고, 동작을 드러내야 하면 "~하기"로 끝낸다. 신문 제목과 보고서 개조식처럼 한국 개발자가 익숙하게 읽는 꼴이다. 저장소 규칙이 제목 꼴을 정해 두었으면(예: 커밋 제목 규칙) 그 규칙을 따르고 어긋남을 알린다.

원인: 규칙이 없었다. 4-3은 표 칸과 그림 글씨만 다루고 제목은 다루지 않았다. 고친 것: 4-5를 더했다. 검사: 책이나 칼럼 제목은 일부러 "~했다"로 끝내기도 해서 `check.py`에 넣지 않았다.

### 사례 8. 사실 목록까지 문장으로 쓰게 한 안내 (2026-11-04)

대상: PR 본문 작성 안내

고치기 전:

> - 주어와 서술어를 갖춘 문장으로 씁니다. 명사로 끊긴 문장(예: "권한 검증 적용.")을 쓰지 않습니다.

처음 고친 문장: 고치기 전과 같다. 3-3을 그대로 옮긴 안내라 korean-sentences가 고칠 곳으로 보지 않았다.

최종:

> - 주어와 서술어를 갖춘 문장으로 씁니다. 문단 안에서 명사로 끊긴 문장(예: "권한 검증 적용.")을 쓰지 않습니다.
> - 다만 바꾼 것이나 코드 위치처럼 사실을 나열하는 목록은 명사로 짧게 끝내도 됩니다. 한 목록 안에서는 끝맺음을 하나로 맞춥니다.

어색했던 까닭: 안내가 PR 본문 전체에 걸려, 바꾼 것을 나열하는 목록까지 "~했습니다"로 끝나는 문장으로 쓰게 만들었다. 사실만 늘어놓는 목록은 명사로 끝낼 때 더 짧고 잘 읽힌다.

정한 것: 사실을 나열하는 목록(무엇을 더했는지, 어디에 두었는지)은 명사로 끝내도 된다. 한 목록 안에서는 꼴을 맞춘다. 리뷰를 부탁하는 칸처럼 까닭이나 부탁을 말하는 항목은 문장으로 쓴다. 명사로 끝내면 까닭과 부탁이 빠지기 때문이다.

원인: 규칙이 없었다. 3-3은 문단 안의 조각 문장을 막으려던 규칙인데 적용 범위가 적혀 있지 않아 목록에도 걸렸다. 고친 것: 3-3에 적용 범위를 적고 4-6을 더했다. 검사: 목록 항목이 사실인지 까닭인지는 글자만 보고 가를 수 없어 `check.py`에 넣지 않았다.
