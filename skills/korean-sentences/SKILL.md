# 문장 개선

규칙은 `references/rules.md`, 개발 용어는 `references/terms/`에 있다. 이 스킬은 둘을 **적용만** 하고 고치지 않는다.

## 절차

1. **대상을 찾는다.** 링크(`file://` URL, 노트 앱 링크 등)로 받으면 URL 디코딩해서 실제 파일 경로를 찾아 읽는다.
2. **규칙과 용어를 읽는다.**
   - `references/rules.md`를 처음부터 끝까지 읽는다. 규칙이 생긴 사례는 `references/cases.md`에 따로 있고, 적용할 때는 읽지 않아도 된다.
   - `references/terms/README.md`와 `references/terms/common.md`를 읽는다.
   - 고칠 문서를 한 번 훑어서, 아래 표의 키워드가 하나라도 보이는 영역 파일을 모두 읽는다. 맞는 파일이 없으면 `common.md`만 쓴다.

   | 영역 파일 | 영역 | 이런 말이 보이면 읽는다 |
   |---|---|---|
   | `references/terms/auth-oauth.md` | 인증, OAuth 2.x, OIDC, JWT | OAuth, OIDC, JWT, JWKS, 토큰, grant, scope, 스코프, Keycloak, SAS, 로그인, 인가, 발급, `client_id`, `Bearer` |
   | `references/terms/database.md` | RDB, SQL, 트랜잭션 | MySQL, SQL, 트랜잭션, 마이그레이션, 스키마, 인덱스, 테이블, `SELECT`, `UPDATE`, JDBC, JPA, Flyway, 격리 수준 |
   | `references/terms/spring.md` | Spring Boot, Spring Security | Spring, 빈, `@Bean`, `@Transactional`, 프로필, Actuator, `SecurityFilterChain`, `application.yml` |
   | `references/terms/aws.md` | AWS 인프라와 배포 | AWS, ECS, ALB, VPC, RDS, IAM, 태스크, 대상 그룹, CloudWatch |

3. **백업한다.** 작업용 임시 폴더의 `backup/`에 원본을 복사하고, 파일의 수정 시각을 적어 둔다.
4. **고친다.**
   - 바꾸는 것: 글 줄의 문장, 표 칸과 그림 글씨의 낱말·수 세기·조사(규칙 4-3), 칸 이름.
   - 바꾸지 않는 것: mermaid가 아닌 코드 블록, 백틱이나 `<code>` 안 식별자, `[[링크]]` 대상, 숫자, 머리말의 키, 파일 경로, 사실.
   - 문장을 풀다가 뜻이 바뀌면 안 된다. 원문에 없는 인과("그래서")나 주장을 더하지 않는다.
   - 이름을 바꾸면(4-4) 문서 안의 제목, 표 머리, 그림 글씨까지 함께 바꾼다.
   - 다른 문서와 함께 쓰는 용어(예: 프로젝트 용어집에 있는 말)는 그 문서들과 이름이 어긋나므로 바꾸지 않는다.
5. **먼저 물어볼 것.** 아래는 고치기 전에 사용자에게 묻는다.
   - 문서 제목이나 파일 이름을 바꿔야 할 때. 바꾸면 다른 문서의 링크도 고쳐야 한다.
   - 다른 문서와 함께 쓰는 용어를 바꿔야 할 때.
6. **쓰기 바로 전에 수정 시각을 다시 본다.** 3단계에서 적어 둔 시각과 다르면 다른 사람이나 세션이 고친 것이다. 쓰지 말고 사용자에게 알린다.
7. **검사한다.** 이 스킬 폴더의 `scripts/check.py`를 실행한다. Markdown(`.md`)과 HTML(`.html`)을 검사한다.
   ```
   python3 <스킬 폴더>/scripts/check.py <문서> --before <백업>
   ```
   - "실패"가 나오면 고친 쪽을 바로잡는다. 코드 블록이 달라졌거나 그림 수가 달라진 경우다.
   - "경고"는 하나씩 본다. 고칠 것은 고치고, 일부러 남긴 것은 보고에 이유를 적는다.
   - 그림 글씨를 고쳤으면 그림이 그려지는지 렌더해서 확인한다.
   - 파일 이름을 바꿨으면 옛 이름을 가리키는 링크가 문서 모음 안에 남았는지 `rg`로 찾는다.
   - `check.py`는 글자만 보고 정해지는 것만 검사한다. 통과했다고 규칙을 다 지킨 것은 아니다.
8. **직접 읽고 확인한다.** 맥락을 알아야 판단되는 것은 기계가 보지 않으므로, 고친 문서를 처음부터 읽으며 아래를 본다.
   - 낱말이 이 글의 맥락에 맞는가 (1-1, 1-2). 예: 소프트웨어 글의 "부품", 권한 확인을 뜻하는 "판정"
   - 개발 용어가 `references/terms/`의 "쓰는 말"과 같은가 (1-3). 먼저 읽은 용어 파일의 "고칠 때 찾아볼 말"을 `rg`로 찾고, 찾은 곳마다 맥락을 보고 정한다. 예: DB 테이블을 "표", 테스트를 "시험"으로 쓰지 않았는가. 문서 안의 표는 "표"가 맞다. 목록에 없는 용어는 원문 그대로 둔다
   - 용어가 겹치면 terms README의 우선순위를 따랐는가. 프로젝트 용어집이 영역 파일보다, 긴 말(Client ID)이 짧은 말(client)보다 먼저다
   - 한 낱말을 한 글 안에서 두 뜻으로 쓰지 않았는가 (1-3). 예: "대역", "주소"
   - 수를 셀 때 단위가 붙었는가 (2-1). 예: "일곱이다" → "일곱 가지다". "셋이 모였다"처럼 단위가 필요 없는 쓰임도 있다
   - 금액·수치 문장이 무엇의 값인지를 주어로 세웠는가 (2-4). "30만 원이 들었습니다"처럼 금액을 주어로 두지 않았는가. "봉투에 만 원이 들어 있다", "계산하니 30만 원이 나왔다"는 맞는 쓰임이다
   - 시점 표현이 값의 성격에 맞는가 (2-4). 기간을 합친 값에 "3월 현재"를 쓰지 않았는가
   - 말투가 글의 쓰임에 맞는가 (4-1, 4-3). 설명 글은 합니다체, 표 칸과 캡션은 짧은 꼴
   - 글에 "~할 겁니다"가 남지 않았는가 (4-2). "제한을 겁니다"(걸다)는 맞는 쓰임이다
   - 문장 안에 종류 괄호를 되풀이하지 않았는가 (5-1)
   - 묶음 이름이 먼저 오고, 꾸밈말이 묶은 항목 모두에 맞는가 (2-3, 3-2)
9. **보고한다.**
   - 바꾼 것을 묶음별로 적는다.
   - 일부러 그대로 둔 것과 그 이유를 적는다.
   - 백업 위치를 알린다.
   - 고치다가 규칙에 없는 어색함을 만나면 그 문장은 직접 고치고, 바꾼 것에 적는다. 규칙은 더하지 않는다.
   - 고친 문장이 읽기에 여전히 어색하면 그 문장을 짚어 달라고 한 줄로 알린다. 짚어 주면 korean-sentences-rules가 원인인 규칙부터 고친다.
10. **사용을 기록하고, 차례가 되면 평가를 받는다.** 문서 하나를 고칠 때마다 보고 뒤에 한 번 실행한다.
   ```
   python3 <스킬 폴더>/scripts/feedback.py use --doc <문서>
   ```
   - 출력이 "평가 요청: 아니오"면 아무것도 하지 않는다.
   - 출력이 "평가 요청: 예"면 보고 맨 끝에서 질문 하나로 평가를 받는다. 질문은 "최근 N번 고친 문장은 어땠나요?"이고, 고르는 답은 네 가지다.

     | 답 | 실행할 명령 |
     |---|---|
     | 그대로 썼다 | `feedback.py rate --score 3` |
     | 조금 손봤다 | `feedback.py rate --score 2` |
     | 많이 손봐야 했다 | `feedback.py rate --score 1` |
     | 건너뛰기 | `feedback.py skip` |

   - 사용자가 까닭이나 어색했던 문장을 함께 말하면 `--note "<한 줄>"`로 적는다. 메모에는 사용자의 말을 한 줄로 줄여 적고, 문서의 내용이나 사람 이름을 옮겨 적지 않는다.
   - 점수가 1이나 2이고 사용자가 문장을 짚었으면 korean-sentences-rules로 넘어가 원인인 규칙을 고친다. 문장을 짚지 않았으면 점수만 적고 더 묻지 않는다.
   - 사용자에게 물을 수 없는 자리(서브에이전트, 자동 실행)에서는 `use`만 실행하고 묻지 않는다. 차례는 기록에 남아서 다음에 사용자와 대화하는 세션이 묻는다.
   - 기록은 스킬 폴더 밖(`~/.claude/korean-sentences/feedback.jsonl`)에 쌓인다. 문서의 내용과 경로는 넣지 않고 문서 형식과 글자 수만 적는다. 쌓인 평가는 `feedback.py summary`로 본다.
   - 평가를 묻는 간격은 기본 다섯 번이다. 환경 변수 `KOREAN_SENTENCES_RATE_EVERY`로 바꾼다.
   - `feedback.py`가 실패해도 문장을 고친 결과는 그대로 보고한다. 기록하지 못했다고 한 줄로 알린다.

## 하지 않는 것

- `references/`의 규칙·사례·용어 목록과 `scripts/`의 스크립트를 고치지 않는다. 그 일은 korean-sentences-rules가 한다.
- 사용자가 고르지 않은 다른 문서를 고치지 않는다. 링크를 고치는 일만 예외다.
- 평가 차례가 아닌데 평가를 묻지 않는다. 한 번 물었는데 답이 없으면 `skip`으로 적고 다시 묻지 않는다.
